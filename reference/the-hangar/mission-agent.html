How it works

Brief in, structured spec out.

Four internal stages — this is the actual architecture being built today, not a simplified version of it.

01 · INPUT PROCESSING

Understand the brief

  • Intent understandingLLM parses free-form input
  • Entity extractionMission, constraints, KPIs
  • Context retrievalRAG against Knowledge Base
  • Validation & normalizationRules engine
02 · REASONING & PLANNING

Decompose the mission

  • Mission decompositionLLM + prompt templates
  • Constraint identificationDomain rules + LLM
  • KPI derivationPerformance, cost, safety
  • Trade-off prioritizationHeuristic / multi-criteria
03 · OUTPUT GENERATION

Structure the spec

  • Mission specificationStructured JSON
  • Constraints listStructured
  • KPIs & targetsStructured
  • Mission summaryNatural language
04 · OUTPUT INTERFACE

Hand off downstream

  • Structured data APIJSON
  • Dashboard viewMission overview UI
  • ExportPDF / DOCX / Excel
  • Event publishTo shared event bus
